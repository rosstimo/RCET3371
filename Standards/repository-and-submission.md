# Repository and Submission Standard

[Standards index](README.md)

## One repository per Programming Assignment

Unless an assignment says otherwise, use one repository per major graded Programming Assignment.

## Required repository quality

A submission repository must:

- contain the complete source needed for grading;
- exclude normal build/cache output;
- contain an appropriate .gitignore;
- have meaningful commit history;
- identify how to build/run/test;
- include required evidence/documentation;
- not contain credentials or secrets.

## README

For larger assignments include:

- purpose;
- build/run instructions;
- required toolchain;
- configuration/data;
- test/verification instructions;
- hardware requirements or fake/simulated path;
- known limitations.

## Commit history

Do not submit one giant final commit unless the assignment explicitly permits it.

History should show meaningful development.

## Submission

Canvas or the current LMS normally receives the repository URL and any specifically requested evidence.

The public code repository itself should not contain private grades or instructor feedback.

## Branch state

Before submission:

    git status

should be understood and intentional.

Push required commits and verify the remote repository contains the version you intend to submit.

## Build from clean clone

For major assignments, test from a clean clone or equivalent clean workspace before final submission.
