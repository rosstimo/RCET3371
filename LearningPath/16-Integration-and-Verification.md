# Section 16 — Integration and Verification

## Outcomes

You should be able to:

- reproduce a build/run/deploy process from documented steps;
- show verification evidence for normal and failure cases;
- explain how repository history reflects design evolution;
- defend responsibility boundaries, language choices, protocol choices, and failure handling;
- distinguish a demonstrated fact from an assumption;
- leave a project understandable and reproducible by another engineer.

## Practice

Audit an existing system for hidden assumptions and missing verification. Reproduce another person's build from documentation only.

Final section assessment and design/verification review.

## Course completion

You should now be able to explain a complete software/hardware system across:

- engineering problem;
- algorithm/state model;
- language construct;
- runtime/toolchain;
- operating-system interface;
- protocol/device boundary;
- processor/hardware behavior;
- verification evidence and implementation tradeoffs.
